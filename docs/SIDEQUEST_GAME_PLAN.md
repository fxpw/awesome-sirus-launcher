# План: замена вкладки «Майнинг» на мини-игру Sidequest

> **Статус: запланировано, реализация не начата.** Текущая позиция Sidequest в общем плане отражена в [ROADMAP.md](ROADMAP.md); все чекбоксы ниже относятся к будущей работе.

Документ описывает концепцию, механики и поэтапную реализацию мини-игры внутри лаунчера.

Цель вкладки — тематический ивент «сервер упал»: пока игровой мир Sirus недоступен, лаунчер даёт короткий idle/arena-луп с персонажем из базы Sirus.

Рабочее название: **Sidequest** (можно переименовать позже).

---

## 1. Зачем это нужно

Сервер Sirus периодически падает или становится недоступен. Вместо вкладки майнинга нужна лёгкая 2D-игра:

- проверяет доступность сервера;
- при дауне принудительно (или с акцентом) уводит игрока в **хаб улучшений**;
- когда сервер жив — даёт бой с манекеном/мобами;
- персонаж берётся из ссылки на базу Sirus: **статы с шмоток и камней** (у магов — сила заклинаний), ilvl как сводка/fallback;
- прогресс сохраняется локально (голда, апгрейды, выбранный персонаж).

Это не замена WoW и не MMO: короткий луп ожидания + лёгкий прогресс.

---

## 2. Высокоуровневый игровой цикл

```text
[Проверка сервера Sirus]
        │
        ├─ online  → Arena (бой / автобой)
        │               │
        │               └─ добровольно → Hub (улучшения)
        │
        └─ offline → принудительный переход в Hub
                         │
                         └─ после восстановления сервера → можно вернуться в Arena
```

### Состояния экрана

| Состояние         | Когда                                              | Что видит игрок                            |
| ----------------- | -------------------------------------------------- | ------------------------------------------ |
| `arena`           | сервер online (или ручной выбор, если уже в арене) | 2D-сцена: персонаж бьёт манекен/моба       |
| `hub`             | сервер offline **обязательно**, или вручную        | улучшения, голда, статусы                  |
| `character-setup` | первый запуск / смена персонажа                    | ввод ссылки на базу Sirus, превью парсинга |
| `event-banner`    | смена online↔offline                               | короткий тематический ивент/уведомление    |

Правило выброса:

- сервер стал `offline` → немедленно `arena → hub` (форс);
- сервер снова `online` → баннер «Мир снова доступен», выход в арену по кнопке (не автофорс из хаба, чтобы не сбивать покупки).

## 3. Ключевые фичи

### 3.1. Проверка доступности сервера

- Периодический health-check (интервал, retry, таймаут).
- Источник статуса: существующие/ближайшие endpoint’ы Sirus (участие API из `secureConnection` / realm status — уточнить на исследовании).
- Состояния: `online` | `offline` | `unknown`.
- При смене статуса — тематический ивент (toast / баннер / смена фона хаба).
- Логировать переходы в journal лаунчера (для отладки).

### 3.2. Импорт персонажа по ссылке на базу Sirus

- Пользователь вставляет URL карточки персонажа с `sirus.su` / базы персонажей.
- Backend (main/core) запрашивает страницу/API и парсит **профиль целиком**, а не только ilvl:
    - имя, класс, фракция, уровень, **ilvl** (сводка / fallback);
    - спек, гильдия — опционально;
    - **экипировка по слотам** (голова…кольца/тринкеты и т.д.);
    - **самоцветы / камни** в сокетах и их бонусы;
    - чары (если отдают в той же карточке) — в том же сумматоре, что и камни.
- Боевые статы Sidequest **собираются суммой с шмоток + камней (+ чар)**, а не выдумываются из одного ilvl.
- `ilvl` остаётся для UI, сравнения персонажей и fallback, если детальный разбор вещи недоступен.

#### 3.2.1. Что парсить со слотов и камней

Суммировать всё, что отдаёт база по предметам и гемам (названия/ключи — как в 3.3.5a / Sirus):

| Группа                 | Примеры полей                                                                               |
| ---------------------- | ------------------------------------------------------------------------------------------- |
| Первичные              | strength, agility, stamina, intellect, spirit                                               |
| Вторичные melee/ranged | attackPower, armorPenetration, haste / attackSpeed rating, hitRating, critRating, expertise |
| Caster                 | **spellPower** (сила заклинаний), spellHit, spellCrit, spellHaste, mp5                      |
| Защитные               | armor, defense, dodge, parry, block (для входящего в Sidequest — по возможности)            |
| Камни                  | те же рейтинги/статы, что у шмоток; плюс socket bonus слота, если виден                     |

Правило: один пайплайн `sumGearStats(items[]) + sumGemStats(gems[])` → `CharacterRawStats` → маппинг в combat-статы класса.

#### 3.2.2. Маппинг в боевые статы Sidequest

Класс решает, **какой пул урона** главный:

| Роль                                              | Primary power                      | Скорость                       | Меткость  | Крит       | HP      |
| ------------------------------------------------- | ---------------------------------- | ------------------------------ | --------- | ---------- | ------- |
| Mage / caster (варлок, лок-спеллы, хил-дд и т.п.) | **`spellPower`** → урон заклинаний | spellHaste                     | spellHit  | spellCrit  | stamina |
| Melee                                             | attackPower (+ str/agi по классу)  | haste / weapon speed если есть | hitRating | critRating | stamina |
| Hunter / ranged                                   | ranged AP / AP                     | haste                          | hitRating | critRating | stamina |

Для **мага** урон автобоя/умений считается от **силы заклинаний** со шмоток и камней, а не от melee-урона.

Аналогично спелл-классы не должны «биться силой» из ilvl-формулы.

Черновой пайплайн:

```text
parse page/API
  → items[] + gems[] (+ enchants[])
  → rawStats = sum(all)
  → combatStats = mapByClass(classId, rawStats)  // mage → spellPower pipeline
  → + hub upgrades
  → arena tick
```

- Кэш профиля + сырого `rawStats` локально; «Обновить» — повторный fetch и пересчёт.
- Ошибки: битая ссылка, недоступна база, пустой список шмоток, неизвестный класс.
- Если по слоту нет статов — слот даёт 0; если **весь** парс шмоток провален — fallback на грубую оценку от ilvl (с пометкой в UI «приблизительно»).

**Открытые вопросы (фаза 0):** формат URL; HTML scrape vs API; отдаёт ли база готовые итоги статов или только предметы/камни по отдельности; как в разметке видны socket bonus и spell power.

### 3.3. Arena — бой 2D

MVP сцены:

- слева/справа спрайт персонажа (по классу или общий);
- напротив — цель(и) комнаты (манекен → пак мобов / босс);
- простая анимация удара / попадания / крита / промаха;
- счётчики: HP целей, нанесённый урон, золото за сессию, тип комнаты.

Эволюция боя:

1. **MVP:** манекен без удара в ответ, автоатака по таймеру от `attackSpeed`, с критами и промахами.
2. **v1:** автобой со сближением к цели, floating combat text (урон / crit / miss).
3. **v2:** комнаты с 1–5 мобами или редким боссом; мобы бьют в ответ.
4. **v3:** умения классов (автокаст по КД или простой приоритет).

### 3.3.1. Механика удара: попадание, крит, скорость атаки

Каждый тик базовой атаки проходит цепочку:

```text
атака готова (attackSpeed)
    → roll попадания (hitChance vs evasion/defense цели)
        → miss → 0 урона, VFX/текст «Miss»
        → hit  → roll крита (critChance)
                   → normal → damage
                   → crit   → damage * critMultiplier
```

Параметры (черновик, конфигурируемые):

| Параметр                | Откуда                                                          | Заметка                          |
| ----------------------- | --------------------------------------------------------------- | -------------------------------- |
| `damage` / spell damage | **шмотки + камни** (AP или **spellPower** по классу) + апгрейды | маг → сила заклинаний            |
| `attackSpeed`           | haste/speed со шмоток/камней + апгрейды + класс                 | выше скорость → чаще удары/касты |
| `hitChance`             | hit / spellHit со шмоток/камней + апгрейды − defense цели       | clamp, например 70–99%           |
| `critChance`            | crit / spellCrit со шмоток/камней + апгрейды + класс            | clamp, например 5–50%            |
| `critMultiplier`        | базово ~2.0 (+ апгрейд)                                         | crit всегда после успешного hit  |
| `hp`                    | stamina (+ связанные бонусы) со шмоток/камней                   |                                  |

Правила:

- промах и крит **взаимоисключающие** на одном ударе (сначала hit/miss, потом crit только при hit);
- мобы/босс используют ту же цепочку против игрока;
- UI: разные цвета/размеры чисел (обычный урон / crit / miss);
- апгрейды в хабе усиливают скорость, меткость и крит отдельно.

### 3.3.2. Комнаты боя: пак мобов или босс

Арена — это не одна цель навсегда, а **последовательность комнат**. После зачистки комнаты сразу генерируется следующая.

Состав комнаты при входе:

```text
roll комнаты
  ├─ ~5–10%  → Boss room (1 босс)
  └─ иначе   → Mob pack: random 1..5 обычных мобов
```

| Тип комнаты | Состав    | Награда                                                | Сложность                                           |
| ----------- | --------- | ------------------------------------------------------ | --------------------------------------------------- |
| `pack`      | 1–5 мобов | голда × число убитых (+ небольшой бонус за full clear) | линейно от размера пака                             |
| `boss`      | 1 босс    | заметно больше голды, шанс «жирного» дропа             | больше HP/урона, выше defense → чаще промахи игрока |

Поведение в комнате:

- цели стоят в ряд / на одной плоскости; автобой идёт по **ближайшей** (или приоритет: низкий HP → ближний);
- пока жив хотя бы один моб/босс — комната не завершена;
- смерть игрока → короткий respawn / возврат в хаб (как в общем правиле арены);
- босс визуально крупнее, отдельный спрайт и SFX; маленький шанс встречи компенсируется наградой.

Числа шанса босса и веса размера пака (1..5) — в конфиге, не в UI-коде.

### 3.4. Классы и умения

- Маппинг классов WoW 3.3.5a / Sirus → игровые архетипы Sidequest.
- На старте: общий набор «базовая атака/каст + 1–2 умения по роли» (melee / ranged / caster), без полного симулятора.
- **Mage и прочие casters** используют pipeline силы заклинаний: автобой = периодический spell-hit от `spellPower`, умения масштабируются от него же.
- Melee/ranged — от attack power и своих рейтингов с тех же шмоток/камней.
- Умения влияют на урон, КД, AOE/DoT — минимум, чтобы отличалось ощущение класса.
- Данные умений и коэффициенты статов — JSON/конфиг в `src/core/sidequest/`, не хардкод в Vue.

### 3.5. Автобой и движение

- Персонаж подходит к мобу на attack range.
- После входа в range — цикл базовой атаки + умения по приоритету.
- Без сложного pathfinding: одна ось / простая 2D-плоскость.
- Пауза боя при уходе в хаб или offline-форсе.

### 3.6. Хаб улучшений

Доступ:

- всегда вручную из арены;
- обязательно при `server offline`.

Покупки за **голду**:

| Улучшение (черновик) | Эффект                                                     |
| -------------------- | ---------------------------------------------------------- |
| Острый клинок        | +% к урону                                                 |
| Укреплённая броня    | +% к HP / −% входящего                                     |
| Скорость ударов      | +`attackSpeed` (чаще автоатака)                            |
| Глаз стрелка         | +`hitChance` (реже промахи)                                |
| Ярость берсерка      | +`critChance` / +`critMultiplier`                          |
| Удача новичка        | +% дропа голды                                             |
| Карта подземелья     | чуть выше шанс boss-комнаты (опционально, поздний апгрейд) |
| Классовый том        | разблок/усиление умения                                    |

Экономика:

- голда с убийств манекена/мобов;
- цены растут (линейно или экспоненциально);
- persist в local storage / settings файл лаунчера.

### 3.7. Тематические ивенты при дауне

Примеры:

- баннер «Мир Sirus недоступен — время тренировок»;
- смена ambient в хабе;
- временный бонус к голде / к опыту тренировок, пока сервер лежит;
- счётчик «минут в хабе за этот даун».

Ивент не должен мешать основному UX лаунчера (патчи, аддоны, запуск игры).

## 5. Техническая раскладка

Предлагаемая структура (черновик):

```text
src/core/sidequest/
  serverStatus.ts       # проверка доступности
  characterParse.ts     # URL → профиль, слоты шмоток, камни, raw stats
  gearStats.ts          # сумма статов со шмоток/камней/чар
  combat.ts             # hit/miss/crit, attackSpeed/haste, тики (AP vs spellPower)
  rooms.ts              # генерация комнат: 1–5 мобов или босс
  classes.ts            # классы / умения / какой primary power
  economy.ts            # голда, цены апгрейдов
  progress.ts           # сериализация сейва
src/main/sidequest/     # IPC-сервис (fetch с CORS, persist)
src/renderer/
  elements/SidequestPanel.vue
  stores/sidequestStore.ts
  sidequest/            # арена canvas/DOM, хаб, setup
assets/sidequest/       # спрайты, sfx (свободные лицензии)
```

Границы процессов:

| Слой       | Ответственность                                 |
| ---------- | ----------------------------------------------- |
| `core`     | чистая логика, формулы, парсинг HTML/DTO, тесты |
| `main`     | network fetch, persist, IPC                     |
| `renderer` | UI, анимации, ввод, отображение боя             |

IPC (черновик каналов):

- `sidequest.getState` / `saveProgress`
- `sidequest.parseCharacter(url)`
- `sidequest.getServerStatus` (+ push event при смене)
- опционально: `sidequest.resetProgress`

Тесты:

- unit: сумма статов со шмоток + камней; mage → spellPower pipeline;
- unit: hit/miss/crit, attackSpeed → число ударов за время;
- unit: генерация комнат (pack 1–5, редкий boss, границы шансов);
- unit: формулы урона от gear-статов, экономика апгрейдов, автобой-тик;
- unit: парсер персонажа на фикстурах HTML/JSON (слоты, гемы, spell power);
- unit: переходы online/offline → forced hub.

## 6. Ассеты

Источник: **бесплатные** наборы с явной лицензией (CC0 / MIT / совместимые с дистрибуцией лаунчера).

Нужно минимум:

- idle / attack персонажа (или набор из 2–3 архетипов);
- манекен + набор обычных мобов + 1 босс;
- VFX/цифры: hit, crit, miss;
- фон арены и фон хаба;
- иконки улучшений;
- SFX: удар, крит, промах, покупка, сервер упал / поднялся, победа над боссом.

Правила:

- фиксировать автора/лицензию в `docs/` или рядом с ассетами (`CREDITS.md`);
- не брать ассеты с неясной лицензией;
- на MVP допустимы цветные плейсхолдеры + замена спрайтами в отдельной задаче.

Кандидаты источников (проверить перед скачиванием): Kenney, OpenGameArt, itch.io (CC0), Craftpix free packs.

## 8. Баланс и формулы (черновик)

Пока ориентиры, не финальные числа:

```text
# статы с парсинга (шмотки + камни + чары), не «голый» ilvl
rawStats       = sum(items) + sum(gems) + sum(enchants)
combatStats    = mapByClass(classId, rawStats) + hubUpgrades

# caster (mage и аналоги)
spellDamage    ≈ rawStats.spellPower * kSp + upgrades
castSpeed      ≈ base + ratingToHaste(rawStats.spellHaste) + upgrades
spellHitChance ≈ clamp(ratingToHit(rawStats.spellHit) + upgrades - targetResist, hitMin, hitMax)
spellCritChance≈ clamp(ratingToCrit(rawStats.spellCrit) + classBase + upgrades, critMin, critMax)

# melee / ranged — зеркально от AP / hit / crit / haste ratings
meleeDamage    ≈ f(attackPower, str|agi) + upgrades
attackSpeed    ≈ baseAps + ratingToHaste(haste) + upgrades
hitChance      ≈ clamp(...)
critChance     ≈ clamp(...)
critMultiplier ≈ 2.0 + critPowerUpgrade
hp             ≈ f(stamina)

# один удар / каст
if random() >= hitChance → Miss (0)
else if random() < critChance → damage * critMultiplier
else → damage

# комнаты
P(bossRoom) ≈ 0.05..0.10
else packSize ~ uniform{1,2,3,4,5}

goldPerKill ≈ base + floor(targetPower * kGold) * (1 + luckUpgrade)
goldBossBonus ≈ packGoldEstimate * bossGoldMult
upgradeCost(level) = baseCost * growth^level

# fallback только при ошибке парса шмоток
approxFromIlvl(ilvl) → грубые combatStats + флаг approximate=true
```

Коэффициенты рейтингов (rating → %) и `mapByClass` — в `gearStats.ts` / `classes.ts` / JSON.

## 9. Риски и ограничения

| Риск                                               | Митигация                                                                          |
| -------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Парсинг базы хрупкий (вёрстка сайта меняется)      | фикстуры + узкий парсер; заранее найти API если есть                               |
| Статы шмоток/камней неполные или в разных форматах | нормализация ключей; socket bonus отдельно; тесты на реальных карточках mage/melee |
| Health-check даёт ложные offline                   | hysteresis (N фейлов подряд), отдельный `unknown`                                  |
| Игра раздувает лаунчер ассетами                    | лёгкие спрайты, лимит пакета, lazy load                                            |
| Баланс «топ шмот = победа всегда»                  | diminishing returns на рейтингах, апгрейды хаба для mid-геймплейа                  |
| Pack 5 мобов / босс слишком жёсткие                | defense и HP в конфиге, мягкий soft-cap меткости                                   |
| Юридически ассеты/товарные знаки Blizzard          | свои/свободные спрайты, без официальных иконок классов без права                   |

## 10. Критерии готовности MVP

MVP можно считать готовым, когда:

1. Вкладка майнинга скрыта, вместо неё Sidequest.
2. Можно добавить персонажа по ссылке и увидеть имя/класс/ilvl **и статы, собранные со шмоток/камней** (у мага — сила заклинаний).
3. Работает бой с автоатакой/кастом от gear-статов: hit / crit / miss; голда копится.
4. Есть комнаты: пак из 1–5 мобов и редкая boss-комната (хотя бы после MVP-манекена в фазе 6).
5. Хаб продаёт улучшения урона/HP и хотя бы скорость или крит/меткость.
6. При offline сервера игрока выкидывает в хаб и показывает ивент.
7. Прогресс сохраняется между перезапусками лаунчера.
