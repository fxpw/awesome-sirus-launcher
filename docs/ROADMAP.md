# Roadmap и статус Awesome Sirus Launcher

Это канонический документ о состоянии продукта: что уже работает, что реализовано частично и что запланировано дальше. История выпущенных изменений ведётся отдельно в [CHANGELOG.md](../CHANGELOG.md), а обязательные технические границы — в [ARCHITECTURE.md](ARCHITECTURE.md).

**Срез состояния:** 24 августа 2026 года, релиз `v1.0.25`.

**Последняя проверка:** `npm run check` — успешно, 22 test-файла и 105 тестов.

Статусы:

- **Готово** — сценарий реализован в backend и UI и покрыт проверками соразмерно риску.
- **Частично** — основной сценарий работает, но известные части ещё не завершены.
- **Запланировано** — задача описана, однако реализация не началась.
- **Не планируется сейчас** — осознанное ограничение текущего roadmap.

Статус «в работе» ставится только после появления реализации в коде или отдельной рабочей ветке. На момент этого среза следующие функции запланированы, но не находятся в активной разработке.

## Что уже сделано

### Основа приложения

- Electron + `electron-vite` + Vue 3 + TypeScript.
- Переносимая доменная логика в `src/core` без Electron-зависимостей.
- Типизированный preload API, Zod-валидация входа и выхода IPC, `contextIsolation` и отключённый Node.js в renderer.
- Русская и английская локализация, тёмный интерфейс и единая главная страница со статусами и быстрыми действиями.

### Клиент и запуск игры

- Выбор и сохранение папки WoW, проверка наличия `run.exe`, `Data`, `Interface` и `WTF`.
- Запуск `<wowPath>/run.exe`, опциональное закрытие лаунчера и остановка внешнего майнера перед игрой.
- Применение выбранного аккаунта к `WTF/Config.wtf` с созданием `.bak`.
- Совместимые с Sirus регистрация устройства, периодический handshake и best-effort MCR-проверка защищённого подключения: сетевой сбой логируется, но не блокирует запуск игры.

### Аддоны

- Встроенный каталог релиза `v1.0.25`: 99 аддонов — 74 community и 25 Sirus.
- Проверка установленных версий по `.toc`, поиск, сортировка, статусы и ссылки на GitHub.
- Установка из GitHub source zip, переустановка, удаление и обновление всех устаревших аддонов.
- Поддержка пакетов с несколькими папками аддонов и пропуск локальных папок с `.git`.
- Пользовательские GitHub-ссылки, импорт и экспорт custom-каталога.
- Прогресс подготовки, скачивания, распаковки и установки.

### Проверка и восстановление клиента

- Manifest с трёх зеркал, rotation/fallback при недоступности выбранного источника.
- Потоковая MD5-проверка, постоянный кэш хешей и ручная очистка кэша.
- Прогресс и отмена сканирования клиента.
- Скачивание одного или всех отсутствующих/повреждённых файлов во временное место, проверка размера и MD5 перед заменой.

### FPS-патч и `WTF`

- Получение remote build/hash FPS-патча, установка с fallback-источником, переустановка и удаление.
- Создание, просмотр, восстановление и удаление zip-бекапов `WTF`.
- Safety-бекап текущего `WTF` перед восстановлением, защита распаковки от выхода за целевую директорию.
- Настраиваемая папка бекапов, открытие её в проводнике и индикация возраста последней копии.

### Аккаунты и GitHub token

- Добавление, выбор и удаление локальных аккаунтов; при удалении очищается связанный секрет.
- Пароли аккаунтов и GitHub token шифруются через `safeStorage`; при недоступном системном шифровании сохранение отклоняется.
- GitHub token используется опционально для увеличения лимитов скачивания и fallback-доступа к GitHub assets.

### Обновление и доставка лаунчера

- Проверка GitHub Releases и сравнение версий по SemVer.
- Выбор подходящего Windows asset: NSIS Setup для установленной версии или Portable exe для portable-запуска.
- Замена и перезапуск portable-версии через отдельный update script.
- Windows Setup с выбором папки и Portable-сборка через `electron-builder`.
- GitHub Actions проверяет согласованность версий, запускает тесты/сборку и публикует релизные артефакты и release notes.

### Дополнительные функции

- Вкладка поддержки авторов.
- Опциональный запуск выбранного пользователем внешнего майнера: явное согласие, видимые аргументы, start/stop и остановка перед запуском игры.
- План замены майнинга на Sidequest подготовлен отдельно; до реализации Sidequest существующая вкладка остаётся доступна.

## Что сделано частично

### Целостность пользовательских данных и обновлений

Сейчас критичные сценарии создают временные файлы или safety-копии, но не все замены полностью атомарны. Нужно:

- распаковывать и проверять выбранный `WTF`-архив до удаления текущей папки;
- заменять аддоны через staged install с rollback при ошибке;
- проверять hash/size FPS-патча до удаления установленной версии;
- проверять размер, checksum или подпись обновления лаунчера и не удалять рабочий portable exe до подтверждённой замены;
- добавить regression/integration tests для неуспешной замены и восстановления.

### Долгие операции

Уже есть прогресс и отмена MD5-сканирования, а также прогресс установки аддонов. Не завершены:

- прогресс и отмена скачивания файлов клиента;
- прогресс и отмена загрузки FPS-патча и обновления лаунчера;
- прогресс и отмена создания/восстановления `WTF`;
- единый жизненный цикл операций `queued → running → succeeded/failed/cancelled` с `jobId`.

### GitHub token

Хранение, использование и очистка token готовы; parser заголовков rate limit покрыт тестами. Осталось:

- валидировать token запросом к GitHub API до сохранения;
- различать 401, 403 и исчерпанный rate limit;
- показывать остаток и время сброса лимита в интерфейсе;
- покрыть Electron secret adapter отдельными contract-тестами.

### Самообновление

Backend уже получает текст release notes, но UI не показывает его перед установкой. Также отсутствуют прогресс скачивания, проверка целостности артефакта и надёжный rollback portable-обновления.

### Настройки, диагностика и privacy

- Добавить кнопку открытия папки клиента в проводнике.
- Обрабатывать повреждённый `settings.json` и ошибки чтения/записи понятным сообщением и безопасным восстановлением.
- Явно объяснять перед регистрацией устройства, какие технические данные отправляются API Sirus.
- Добавить структурированный журнал операций вместо разрозненных console-сообщений.

### CI и тесты

- Разделить обычный CI для изменений `src/**`/`tests/**` и релизную публикацию по изменению версии.
- Добавить renderer component tests и Electron/Playwright smoke tests.
- Сохранить обязательные unit-, schema-, integration- и portability-проверки.

## Следующие этапы

Версии и сроки для следующих задач пока не назначены. Порядок ниже отражает рабочий приоритет по риску и зависимости задач.

### P0 — надёжность существующих сценариев

1. Staged/atomic замена для `WTF`, аддонов, FPS-патча и portable-обновления.
2. Проверка целостности скачанных патчей и обновлений до замены рабочих файлов.
3. Единый прогресс и отмена скачиваний, backup/restore и установки обновлений.
4. Валидация GitHub token, понятные 401/403 и rate limit в UI.
5. Preview release notes перед установкой, privacy-описание регистрации устройства и исправление устаревших текстов настроек.

### P1 — Sidequest: исследование и каркас

Статус: [подробный план](SIDEQUEST_GAME_PLAN.md) подготовлен, код не начат.

1. Проверить стабильный способ определения статуса сервера Sirus.
2. Исследовать URL персонажа и получение экипировки, камней и combat-статов, включая `spellPower`.
3. Выбрать DOM/CSS, Canvas или лёгкий движок для боя.
4. Добавить скрываемую/заменяемую вкладку `SidequestPanel`, локальный сейв, пустые Arena и Hub.
5. Скрыть майнинг из пользовательского пути, сохранив backend до завершения миграции.

### P2 — Sidequest MVP

1. Polling статуса сервера, состояния `online/offline/unknown` и переход в Hub при offline.
2. Импорт персонажа и маппинг экипировки/камней в статы класса.
3. Автобой с hit/miss/crit, уроном, скоростью и сохранением голды.
4. Hub с базовыми улучшениями и понятной черновой экономикой.
5. Тесты формул, парсинга, persistence и переходов состояния.

### P3 — развитие продукта

- Комнаты Sidequest с 1–5 мобами, редким боссом, ответным уроном, классовыми умениями и лицензированными ассетами.
- Полировка Sidequest и удаление устаревшего mining-кода после миграции.
- Отдельный экран журнала операций и ошибок.
- Полный CRUD custom-аддонов, inventory неизвестных папок, pinned tag/commit и ручной zip fallback.
- Retention/лимиты старых `WTF`-бекапов.
- Автообновление **пользовательских конфигураций аур** WeakAuras с safety backup и разрешением конфликтов. Установка самого аддона WeakAuras из каталога уже работает.
- Playwright smoke для первого запуска, выбора клиента, проверки/ремонта и запуска игры.

## Не планируется сейчас

- Установка полного клиента Sirus с нуля: лаунчер работает с уже существующей папкой игры.
- Code signing без доступного сертификата: Windows-сборки остаются неподписанными и могут вызывать SmartScreen.
- Отдельные релизные сборки для macOS/Linux: текущий продукт и системные сценарии ориентированы на Windows.
- Для Sidequest: мультиплеер/PvP, полноценный симулятор WoW-ротаций, реальные платежи и мобильная версия.

## Как поддерживать этот документ

- При завершении функции переносить её из «Частично»/«Следующие этапы» в «Что уже сделано» в том же изменении кода.
- Не считать план реализованным только по наличию design-документа или core-типа: пользовательский сценарий должен быть подключён к backend и UI.
- Для истории релизов обновлять `CHANGELOG.md`, не превращая roadmap в журнал коммитов.
- Номер версии меняется только при подготовке отдельного релиза; обычное обновление roadmap остаётся в `[Unreleased]`.
